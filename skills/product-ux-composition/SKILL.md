# Product UX Composition

사용자가 정보를 보고 다음 행동을 고르기 쉬운 화면을 만든다. 기존 제품의 시각 언어와
기능·저장 의미를 보존하면서 행동의 우선순위, 서로의 관계, 정보 밀도를 조정한다.
특정 카드 스타일이나 모든 앱에 같은 레이아웃을 강제하지 않는다.

해당 앱의 지침과 최신 사용자 결정을 우선한다. React Native 작업에서는
대상 프로젝트의 `docs/rn-foundation-ui/README.md`(저장소 UI 경계)를 따른다. 이 스킬은 제품 구성을
다루며 native ownership 기준이나 실제 기기 검증을 대신하지 않는다. J Plan 작업이거나
이 원칙의 적용 사례가 필요하면 [J Plan 사례](references/j-plan-lessons.md)를 읽는다.
앱별 시간 범위·색상·탭 구성·검색 지연값을 다른 제품의 기본 규칙으로 옮기지 않는다.

## 행동의 관계부터 설계한다

- **버튼을 기능별로 한 행씩 세로로 늘어놓는 배치를 금지한다.** 주요 행동, 같은 맥락의
  보조 행동, 위험한 행동을 먼저 구분하고 크기·위치·강조를 정한다.
- 주요 저장·실행 버튼이 한 행의 넓은 영역을 쓰는 것은 가능하다. 그 아래에 모든 부가
  기능을 똑같은 크기의 전체 너비 버튼으로 계속 쌓지 않는다.
- 선택 옵션이 주 행동보다 강하게 보이지 않게 한다. 이동수단 같은 선택은 납작한 탭을
  검토하고 선택 상태에만 약한 강조를 준다. 선택됨은 색상 외에도 접근성 상태로 전달한다.
- 관련 행동은 같은 행이나 해당 콘텐츠 가까이에 묶는다. 부가 행동은 알아볼 수 있는
  아이콘·텍스트 버튼·메뉴로 줄인다. 서로 무관한 행동을 무조건 가로로 모으지도 않는다.
- 같은 일을 하는 버튼·숏컷은 한 화면에 반복하지 않는다. 다른 위치의 숏컷을 추가할
  때는 실제로 다른 사용 맥락을 해결하는지 먼저 확인한다.
- 삭제 등 위험한 행동은 danger 표현과 분리된 위치를 사용한다. 확인 또는 되돌리기는
  제품 요구와 실수 비용에 맞게 제공한다. 아이콘으로 바꿔도 의미와 복구 가능성을 숨기지 않는다.
- 추가·복제를 쉽게 만들면 삭제·취소도 찾기 쉬운지, 순서 이동에 반대 방향이 빠지지
  않았는지 함께 확인한다. 사용자 지정 순서를 다루는 목록은 추가와 순서 조정을 같은 맥락에서 제공한다.
- 아이콘에는 접근성 이름과 충분한 터치 영역을 유지한다. 의미가 모호하면 짧은 라벨을
  남긴다. 유사한 기능끼리는 아이콘의 형태도 구분한다. 시각 높이를 줄이려고 터치 영역까지
  줄이거나, 모든 기능을 아이콘만으로 바꾸지 않는다.

예를 들어 메모 폼 하단은 `[첨부 아이콘] [메모 저장 — 남은 너비]`로 구성할 수 있다.
장소의 핵심 길찾기와 보조 지도 열기도 `[지도 아이콘] [길찾기 — 남은 너비]`로 묶을 수 있다.
이 예시를 서로 다른 의미의 모든 화면에 복제하지 않는다.

## 제품 문구는 앱 사용자를 위해 쓴다

- 구현 방식, 데이터 구조, 개발 의도, 기능을 구현했다는 보고를 제품 화면에 넣지 않는다.
  각 문장이 사용자의 선택·행동·상태 이해에 어떤 도움을 주는지 확인한다.
- 행동을 바꾸지 않는 소개 문장, 당연한 절차 설명, 반복 제목·라벨, 장식용 태그는 제거한다.
  설명을 추가하기 전에 이름·아이콘·배치·상태 표현으로 이해할 수 있게 만든다.
- 완료 상태가 목록에서 이미 드러나면 별도 축하·완료 카드로 공간을 차지하지 않는다.
  빈 상태의 다음 행동, 저장 실패와 권한 안내까지 함께 지우지는 않는다.
- 같은 정보가 제목·카드·버튼에 반복되면 필요한 위치 한 곳에 남긴다. 좌표·내부 ID 같은
  원시 값은 해당 사용자의 실제 작업에 필요할 때만 노출한다. 화면에서 숨겨도 원본 데이터는 보존한다.
- 저장 완료 같은 짧은 피드백은 toast 등으로 전달한다. 사용 방법은 필요할 때 펼쳐 보는
  안내로 제공한다. 해결이 필요한 실패, 입력 오류, 권한·필수 고지는 적절한 위치에 남긴다.
- 긴 설명을 툴팁이나 toast로 그대로 옮겨 숨기지 않는다. 먼저 필요성과 분량을 줄인다.
  앱의 사용자 문구와 개발 완료 리포트는 각각의 독자에 맞게 별도로 작성한다.

## 목록의 역할과 상세의 깊이를 정한다

- 한 화면의 주 작업을 먼저 정한다. 보관 목록이 외부 검색·온보딩·설정으로 밀려나지
  않게 한다. 관련 없는 설정은 설정 상세로 옮기고 안내는 필요할 때만 펼친다.
- 목록은 이름과 판단에 필요한 짧은 정보부터 보여준다. 날짜·기간·개수 등은 타이포와
  그룹으로 위계를 주되 불필요한 경로 미리보기나 장식용 카드를 늘리지 않는다.
- 사용자가 먼저 확인할 콘텐츠를 앞에 두고 그에 대한 행동을 가까이 배치한다. 기록용
  컨트롤이나 덜 쓰는 옵션이 주요 계획·콘텐츠보다 큰 영역을 차지하지 않게 한다.
- 여러 묶음을 함께 훑는 작업에는 인라인 펼침/접힘을 사용한다. 펼침 아이콘과 상세 진입이
  둘 다 있다면 역할을 분명하게 구분하고 여러 묶음을 동시에 비교할 수 있게 한다.
- 독립적인 상세 작업은 페이지, 짧고 한정된 보조 입력은 sheet를 검토한다. 자체 보조
  sheet가 필요한 상세를 다시 sheet 안에 쌓지 않는다. 지도·폼을 중복으로 띄우지 않는다.
- 상세의 대상 이름과 뒤로 가기는 진입 즉시 알아볼 수 있게 한다. 스크롤 위치에 따라
  제목이 잠깐 사라지거나 같은 제목이 두 곳에서 경쟁하는 구성을 피한다.
- 단순 상태는 폭이 허용하는 한 라벨·현재 값·토글을 한 행에서 중앙 정렬한다. 값이 생긴
  뒤에도 정렬을 유지하고, 큰 글자·긴 번역을 고정 높이로 자르지 않는다. 켰을 때 필요한
  부가 입력만 드러낸다. 자동 기록 값은 바로 보여주고 필요할 때 눌러 수정하게 한다.

## 입력의 부담과 저장 의미를 함께 줄인다

- 현재 도메인에 맞는 native 입력을 우선 검토한다. 기본 시계로 표현할 수 없는 확장
  시각·기간은 native 시/분 Picker 등으로 선택하게 하고 수동 콜론 입력을 요구하지 않는다.
- 같은 시간 선택 동작은 앱 공용 컴포넌트에 모아 범위·형식·확정 방식을 함께 바꿀 수
  있게 한다. 시각과 기간의 의미, 문자열과 분 단위 같은 저장 계약까지 같다고 취급하지 않는다.
- 편집 중 임시 값과 저장 값을 구분한다. 확정이 필요한 편집에는 알아볼 수 있는 확인·취소를
  제공하고 닫기·X·접기·토글에 저장 의미를 숨기지 않는다. 단순 on/off의 즉시 저장은 유지할 수 있다.
- 기본 뒤로 가기·dismiss가 안전하게 초안을 취소하면 중복 취소 버튼은 덜어낸다.
  값 편집에 필요한 명시적 취소까지 일괄 제거하지 않는다. 열기·취소만으로 기존 값을 바꾸지 않는다.
- 숫자만 남기기·허용 범위 보정처럼 제품이 허용한 가벼운 보정에는 alert를 남발하지 않는다.
  중요한 실패나 데이터 손실은 조용히 보정하지 않는다. 허용 범위 자체는 앱의 도메인에서 정한다.
- 카테고리가 이미 구분해 주는 내용을 제목으로 또 입력하게 하지 않는다. 카테고리별로
  필요한 필드만 추가하고, 제거한 필드의 기존 사용자 내용은 보존한다.
- 검색어 입력은 즉시 반영하고 필요하면 결과 필터에만 디바운스를 둔다. 키보드가 열려도
  결과가 보이고 한 번의 탭으로 선택돼야 한다.

## 화면 전환도 디자인 범위에 넣는다

- 여행·프로젝트 같은 작업 대상을 바꾸면 선택을 해석·저장한 뒤 목표 화면으로 직접
  연결한다. 새로 만든 항목도 최신 상태에서 찾으며 빈 중간 페이지를 경유시키지 않는다.
- 준비 중에는 현재 맥락에서 진행 상태를 보여주고 중복 실행을 막는다. 내부 바로 가기와
  외부 링크의 대상 해석을 일관되게 하고 없는 대상을 임의의 현재 항목으로 대체하지 않는다.
- 화면 포커스·선택 변경으로 원본 계획이나 실행 기록이 바뀌지 않게 한다. UI에서 숨기는
  정보와 삭제하는 데이터, 보류하는 기능과 지우는 기록을 구분한다.
- 네이티브 header/back, scroll, sheet dismiss, 입력·포커스는 현재 플랫폼과 저장소의
  ownership 기준을 따른다. 입력이 열릴 때 확인 버튼까지 도달할 수 있게 기본 scroll API로
  드러낸다. 스크롤·키보드 위치나 화면 전환 완료를 고정 화면 높이·지연 시간으로 추측하지 않는다.
- 목록 스크롤과 선택 중 의도하지 않은 외부 앱 전환이 발생하지 않게 한다. 외부 실행은
  사용자가 목적지와 행동을 알아볼 수 있는 명확한 컨트롤에 연결한다.

## 변경과 검토

1. 해당 앱의 지침과 현재 화면에서 주 작업·보존할 동작·데이터를 확인한다. 현재 화면의
   캡처가 있으면 코드와 함께 대조한다. 과거 리포트의 옛 화면을 현재 요구보다 우선하지 않는다.
2. 주요/보조/위험 행동과 정보 위계를 정한다. 새 화면이나 큰 구성 변경은 Product Design 등
   사용 가능한 디자인 도구로 시안을 검토하고, 사용자가 도구를 지정했다면 해당 스킬을 따른다.
   작은 색·간격 조정까지 매번 새 디자인 탐색으로 늘리지 않는다.
3. 각 컨트롤이 필요한지, 왜 그 콘텐츠와 그 위치에 있는지 대조한다. 단순 가로 정렬,
   전면 아이콘화, 설명을 숨기는 것으로 검토를 대신하지 않는다. 반복되는 동작을 공용화하되
   디자인 개선을 이유로 제품 범위·유료 연동·아직 준비되지 않은 기능을 추가하지 않는다.
4. 구현과 검토를 구분하고 사용자의 변경 요청을 항목별로 다시 대조한다. 변경된 범위에서
   값 유무, 긴 내용·번역, 키보드·열린 편집기, 저장·취소 후 상태와 뒤로 가기 중 관련 항목을 확인한다.
   navigation·sheet·gesture·입력처럼 네이티브 동작을 바꿨다면 그 흐름을 실행해 관찰한다.

리뷰에는 사용자가 겪는 구체적인 문제와 최소 변경을 적는다. 지키지 못한 제품 원칙은
밝히되, 정적 판단·실제 관찰·미검증을 구분한다. 이 스킬은 기능 제거·데이터 삭제·서버 변경이나
추가 외부 작업의 권한을 부여하지 않는다.
