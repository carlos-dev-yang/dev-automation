# J Plan에서 확인한 적용 사례

J Plan을 다루거나 공통 원칙을 구체적인 화면에 적용할 때 읽는다.
이 문서는 설계 판단의 사례이며 별도의 앱 규칙집이 아니다. 현재 제품 결정은
[J Plan AGENTS.md](../../../../apps/j-plan/AGENTS.md)와 최신 사용자 지시를 따른다.
이전 리포트의 화면·수치를 최신 기본값으로 복원하지 않는다.

## 피드백을 설계 판단으로 바꾸기

| 실제 문제 | 적용한 판단 | 다음 작업에서 확인할 것 |
| --- | --- | --- |
| 길찾기·지도 열기·첨부·저장이 각각 전체 너비 버튼으로 쌓임 | 주요 실행은 넓게, 관련 보조 행동은 같은 행의 작은 아이콘으로 배치 | 주 행동을 먼저 찾을 수 있는가. 의미가 다른 버튼을 억지로 한 행에 넣지 않았는가 |
| 이동수단 선택이 길찾기보다 더 강하게 보이고 차량 아이콘끼리 비슷함 | 낮은 탭과 선택 항목의 연한 secondary 배경, 구분되는 아이콘 사용 | 미선택 배경을 없애도 선택 상태와 접근성 이름이 분명한가. 터치 영역은 유지되는가 |
| 목록에 예상 이동시간·이동 메모·좌표·완료 카드가 반복됨 | 목록은 목적지와 상태에 집중하고 상세·메모에서 필요한 정보를 제공 | 완료 안내를 덜어내면서 빈 상태의 다음 행동이나 저장 실패도 없애지는 않았는가 |
| 일정과 방문 sheet 안에 길찾기 sheet와 미니맵이 다시 열림 | 목적지 상세는 Stack 페이지, 길찾기는 인라인, 메모 추가만 보조 sheet | 진입 즉시 이름·뒤로 가기가 보이는가. 지도·폼이 중복으로 mount되지 않는가 |
| 날짜별 목록이 개수만 표시해 여러 날의 내용을 비교할 수 없음 | 날짜별 카드에서 목적지 목록을 펼치고 편집은 기존 D-day 화면으로 연결 | 펼침과 상세 진입이 구분되는가. 같은 편집 흐름을 두 벌 만들지 않았는가 |
| 장소를 추가한 화면에서 순서를 바꿀 수 없고 복제보다 삭제가 어려움 | 같은 목록에서 길게 누르기·짧은 haptic·드래그 정렬, 날짜 이동은 위·아래 제공 | 재진입 없이 조정 가능한가. 복제·삭제 확인과 취소, 저장 후 순서도 맞는가 |
| 시간에 콜론을 직접 입력하고 다음 날 토글·접기·X의 의미가 모호함 | 앱 공용 TimeFields에서 native 시/분 선택과 명시적 확인·취소 제공 | 임시 선택·확정·취소·지우기가 구분되는가. 기존 값과 저장 단위가 보존되는가 |
| 방문 토글을 켠 뒤 시간 표시가 생기면서 정렬이 어긋남 | 라벨·시간·토글을 한 행에서 중앙 정렬하고 켜면 현재 시간 기록 | 값이 없을 때와 생긴 뒤 모두 정렬되는가. 편집 확인 버튼까지 보이는가 |
| 메모 카테고리와 필수 제목이 같은 내용을 두 번 요구함 | 제목 없이 내용 중심, 일정·교통편에만 선택 시간 제공 | 필드를 덜어내도 예전 제목·내용이 사라지지 않는가 |
| 보관함 안내·외부 검색·설정이 저장 목록을 아래로 밀어냄 | 저장 목록과 검색을 먼저, 공유 도움말은 ?, 외부 검색은 보조, 설정은 독립 탭 | 키보드가 떠도 결과가 보이고 한 번에 선택되는가. 입력과 결과 갱신이 분리되는가 |
| 여행을 바꿀 때 빈 중간 페이지를 거쳐 이동 화면이 다시 나타남 | 최신 상태로 대상을 해석·저장한 뒤 직접 전환, 준비 중에는 기존 맥락 유지 | 새 여행 생성 직후·기존 여행 선택·장소에서 일정 바로 가기가 모두 같은 목적지에 연결되는가 |

## 이 앱에만 적용하는 현재 범위

- Contour와 기존 컬러톤을 유지한다. 수치 정보의 시각 위계를 만들되 경로 미리보기나
  서버에 없는 공유 인원·아바타를 장식용으로 추가하지 않는다.
- 시간 선택은 공용 [TimeFields](../../../../apps/j-plan/src/shared/ui/time-input.tsx)의
  시 00–29 / 분 00–59다. 기존 30시 이상 값은 확인 전까지 보존한다.
  시각 문자열과 기간의 분 단위 저장은 구분하며, 정확한 허용 범위는 다른 앱에 강제하지 않는다.
- 보관함 결과 필터는 300ms 디바운스하고 입력 자체는 지연하지 않는다. 이 수치는 모든 검색의 표준이 아니다.
- Google Maps는 실제 장소·경로·시간 확인을 맡고 J Plan은 검증한 장소와 순서·메모를 관리한다.
  UI 작업을 이유로 유료 검색이나 미완성 공유 수집함을 추가하지 않는다.
- 기록 비교는 보류되어 있지만 서버 공유·멤버 관리·공동 메모와 공개 스냅샷은 현재 기능이다.
  공개본은 소유자가 수동으로 갱신하며 원본 여행과 자동 동기화하지 않는다.
  화면을 정리해도 기존 기록과 원본 장소 식별자·좌표·URL은 보존한다.
  현재 기능 범위는 앱의 AGENTS.md와 온라인 공유 구현 문서를 따른다.

## 근거와 재검토

- [여행 선택·장소 연결 디자인](../../../../apps/j-plan/docs/journey-links-2026-11-01/DESIGN.md):
  기존 Contour의 정보 위계, 직접 여행 선택, 공통 진입 설계의 근거.
- [공용 시간 입력·전환 런타임 리포트](../../../../apps/j-plan/docs/time-controls-2026-11-01/REPORT.md):
  iOS → Android 실제 선택·취소·저장, 방문 행 정렬, 새 여행 직후 전환과 화면 캡처.

이 근거는 당시 변경 범위의 관찰이다. 이후 변경의 런타임 검증이나 스크린리더 검증을 대신하지 않는다.
